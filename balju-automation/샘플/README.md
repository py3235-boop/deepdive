# 샘플 데이터

동작을 재현하고 확인하기 위한 **테스트용 더미 데이터**입니다. 실제 사내 데이터가 아닙니다.

드라이브의 폴더 구조를 그대로 옮겨 놓았습니다.

```
샘플/
├── 고객사 첨부파일/
│   ├── 고객사A/                     (비어 있음 — 아래 설명 참조)
│   ├── 고객사B/  고객사B 9월 발주서.png
│   └── 고객사C/  고객사C 9월 발주서.pdf
└── 필요 첨부파일/
    ├── 변환규칙.xlsx
    └── 고객사 발주서 양식.xlsx
```

---

## 세 고객사가 서로 다른 형식으로 온다

| 고객사 | 형식 | 추출 경로 | 데이터 |
|---|---|---|---|
| **A** | **메일 본문 표** (첨부 아님) | HTML `<table>` 파싱 | 데이터 8행 + 합계 3행 |
| **B** | 이미지 (`.png`) | Drive OCR (`ocrLanguage: 'ko'`) | 데이터 7행 + 소계 1행 |
| **C** | PDF (텍스트 레이어) | Drive 변환 | 데이터 1행 + 합계 1행(계산) |

### 고객사A — 폴더가 비어 있는 이유

고객사A 는 **메일 본문에 표로** 보내옵니다. 첨부 파일이 없어 폴더에 넣을 것이 없습니다.

시험해 보려면 아래 조건으로 자기 계정에 메일을 한 통 보내면 됩니다.

- 제목이나 본문에 **`고객사A`** 와 **`발주`** 가 들어갈 것
- 본문에 **표**가 있을 것 (엑셀·구글시트에서 복사해 붙이면 HTML 표가 된다)

표 구조:

| 업체코드 | 업체명 | 코드 | 발주코드 | 품명 | 수량 | 중량 | 일자 | 출고코드 | 출고처 |
|---|---|---|---|---|---|---|---|---|---|
| 116308 | 딥다이브 | ZWCSS-00030 | ZWCSS-00030-P | 0.3SQ | 9 | 3,780 | 20260908 | 199920 | 고객사 A |
| 116308 | 딥다이브 | ZWCSS-00050 | ZWCSS-00050-P | 0.5SQ | 9 | 3,780 | 20260908 | 199920 | 고객사 A |
| 116308 | 딥다이브 | ZWCSS-00200 | ZWCSS-00200-P | 2.0SQ | 11 | 4,796 | 20260908 | 199920 | 고객사 A |
| 합계 | | | | | 29 | 12,356 | | | |

납기 블록이 여러 개이고 **블록마다 끝에 `합계` 행**이 붙습니다.
합계 행은 검산 기준이 되므로 실제 행들의 합과 맞아야 합니다.

## 참조 시트 두 개

이 둘은 **드라이브에 스프레드시트로 올려야** 동작합니다 (`필요 첨부파일` 폴더).
여기 있는 `.xlsx` 는 그 원본입니다.

### `변환규칙.xlsx`

고객사가 쓰는 코드·규격을 딥다이브 품목코드로 잇는 표. 고객사마다 탭이 하나씩 있습니다.

| 고객사 | 찾는 키 |
|---|---|
| A | `코드` (`ZWCSS-00030`) |
| B | `규격` (`7/0.260`) — 품명이 전부 `연동집합선` 이라 구분에 못 쓴다 |
| C | `제품명` + `규격` |

고객사C 탭에는 `중량` 열이 있는데, 이것이 **규격별 단위중량**입니다. 검산에 씁니다.

### `고객사 발주서 양식.xlsx`

**출력 표의 모양 그 자체**입니다. 필드 대응표가 아닙니다.

```
1행:  [고객사 X 병합]        (빈 열)   [딥다이브 병합]
2행:  발주코드 | 품명 | 수량 | 중량 | 일자  │  품목 | 품목코드 | 규격 | 수량 | 중량 | 일자
```

왼쪽에 고객사 원본, 빈 열 하나, 오른쪽에 변환 결과가 들어갑니다.
코드가 이 시트를 읽어 탭 레이아웃을 만들므로, **여기를 고치면 산출물 모양도 따라 바뀝니다.**

## 이 샘플로 확인할 수 있는 것

| 항목 | 기대값 |
|---|---|
| 고객사B 소계 검산 | 7행 합 = 69,794 |
| 고객사C 단위중량 검산 | 16 × 436 = 6,976 |
| 고객사A 블록 합계 검산 | 8항목 (블록 3개 × 수량·중량 + 단위중량 2) |
| 규격 표기 정규화 | 발주서 `7/0.26` ↔ 변환규칙 `7/0.260` |
| 품목명 누락 처리 | `30/0.173` 은 품목명이 비어 있어도 매핑은 성공 |

이미지 OCR 로 읽은 고객사B 가 **7행 전부 정확히** 나오고 소계까지 맞는 것이,
외부 API 없이 Drive OCR 만으로 충분하다는 근거입니다.
