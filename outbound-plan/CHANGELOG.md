# 변경 이력

개발 중 실제로 실행해보면서 발견하고 고친 문제들을 파일별로 정리한다. git 커밋 메시지가
"README 추가" 같은 묶음 작업 단위라 파일별 변경 이유가 안 보여서 별도로 남긴다.

## TruckBucket.gs (핵심 배분 엔진)

- **하루 상한 초과 버그** — "연속값으로 나눈 뒤 단위중량 배수로 반올림"하던 방식은 반올림 오차가
  다른 날짜로 넘어가면서 트럭 상한(5,000kg)을 다시 넘기는 문제가 반복됐다. 처음부터 끝까지
  단위중량(보빈) 1개씩만 배정하는 라운드로빈으로 전면 재작성해서 구조적으로 막았다.
- **여유일 선택 우선순위 버그** — 이미 다른 업체로 꽉 찬 "무거운 날"이 기준일과 하루 이상 떨어진
  날이라는 이유만으로 "가벼운 날"보다 먼저 뽑히는 경우가 있었다. 가벼운 날을 최우선 기준으로
  재정렬했다.
- **여유일 판정 임계값 오류** — 트럭대수가 임계값(2대)에 정확히 도달한 날도 "아직 여유 있음"으로
  판정하던 걸(`<=`), 이미 꽉 찼다고 보도록(`<`) 고쳤다.
- **생산capa 부족 처리 방식 변경** — capa가 그 주에 전혀 안 열리면 예전엔 무시하고 강행 배정했다.
  이제는 배정을 건너뛰고 생산이 쌓인 다음 주로 미룬다(월말까지 정말 못 채우면 최후수단으로 강행).
- **소량 자투리 병합 추가** — capa가 트럭 절반(2,500kg) 미만만 열린 날에 단독 배정되던 자투리를,
  안전할 때만(트럭 상한·생산capa 안 넘길 때만) 그 품목의 다음 배정일로 합치는 후처리를 추가했다.
- **위 병합 로직 자체의 버그 수정** — 단위중량을 모르는 품목은 별도 버킷(`allBuckets`)을 쓰는데
  병합 로직이 이걸 몰라 `companyBuckets`를 잘못 건드리던 버그, 그리고 `vendorDateLoad`를 라이브
  버킷 값 기준으로 되돌리다가 다른 업체 몫을 잘못 깎아먹던 버그를 수정했다.

## Main.gs / ActualShipment.gs

- **vendorDateLoad 중복 반영 버그** — 트럭버킷 타입은 내부에서 이미 트럭대수를 갱신하는데, 바깥의
  공통 합산 로직이 또 더해서 실제보다 부풀려졌다. 트럭버킷 타입은 내부 갱신만 신뢰하고, 균등분배
  타입은 날짜별 kg 총합을 한 번만 트럭대수로 환산하도록 고쳤다.
- **업체 처리 순서 버그** — 요일이 고정된 업체보다 트럭버킷 업체를 먼저 처리하면, 트럭버킷 쪽이
  아직 반영 안 된 고정형의 미래 부하를 몰라서 같은 날에 겹쳐 배정하는 일이 있었다. 고정형을 먼저
  처리하도록 순서를 바꿨다.
- 신규/변경 품목 표시(발주스냅샷 대비), 발주량 컬럼, 구글챗 알림 연동 추가.
- **생산capa 검증 스킵 조건 버그(치명)** — 품목에 기초재고/적정재고는 있는데 이번 달 설비를 하나도
  못 받은 경우(`producedByDate`가 비어있음)를 "검증 데이터 없음"으로 오인해서 검증을 완전히
  스킵(무제한 취급)했다. 실제로는 정반대로 가장 위험한 케이스라, 기초재고/적정재고가 둘 다 없을
  때만 스킵하고 나머지는 생산량 0으로 취급하도록 `ProductionCapa.gs`와 함께 고쳤다.
- **자동/수동 실행 구분 표시 추가** — 자동 감지 트리거로 실행됐는지 메뉴에서 사람이 직접 실행했는지
  챗 알림·실행이력에 `[자동실행]`/`[수동실행]`으로 남기도록 `executionType` 인자를 추가했다.
- **신규 품목과 발주량 변경 품목을 구분** — 기존엔 `row.changed`(boolean) 하나로 뭉뚱그려서 둘 다
  같은 빨간 글씨로 강조했다. `row.changeType`('new'/'changed'/null)로 나눠서 `WritePlan.gs`가 서로
  다른 색으로 그리게 하고, 챗 알림도 "신규 N개 · 변경 M개"로 분리해서 보여주도록 고쳤다.
- **동시 실행 충돌로 인한 실패** — 자동 감지 트리거가 도는 도중에 수동 실행이 겹치면, `OrderSnapshot.gs`의
  "탭 있으면 쓰고 없으면 만들어라" 로직이 동시에 같은 탭(`발주중량`)을 만들려다 "이름이 'X'인 시트가
  이미 있습니다" 오류로 실패하고 🚨 알림이 울렸다. `generatePlan()`/`applyActualShipment()` 둘 다
  `LockService.getScriptLock()`으로 감싸서, 겹쳐 실행되면 뒤에 들어온 쪽은 최대 30초 대기 후 에러
  없이 건너뛰도록 고쳤다.
- 알림/로그 문구를 "검증 경고"에서 "검증사항"으로, 경고 삼각형 아이콘(⚠️)을 일반 아이콘(ℹ️/📋)으로
  바꿨다(내용은 그대로, 표현만 덜 자극적으로 변경).

## ReadOrders.gs / ReferenceFiles.gs

- **Drive API v2/v3 호환성 버그** — xlsx 발주서/참고파일을 구글시트로 변환할 때 `Drive.Files.insert`가
  Drive API v3 환경에서는 없어서 실패했다. `Drive.Files.create`(v3)/`insert`(v2) 둘 다 지원하도록
  분기 처리했다.
- `Holidays.gs`, `WeightLookup.gs`를 `ReferenceFiles.gs`로 통합(파일 수 정리).
- **업체 발주 전체가 조용히 누락되던 문제** — 발주서 탭이 "고객사 X" 이름은 맞는데 "딥다이브" 마커나
  품목코드/중량 헤더를 못 찾으면, 그 업체 발주가 경고 없이 통째로 빠졌다. 이제 `loadOrderStatus()`가
  이런 경우를 issues로 반환해서 검증사항·실행이력·챗 알림에 노출한다(재계산을 스킵하는 실행에서도
  이 경고만은 매번 알린다).
- **`고객사 X 원본` 참고 탭이 발주서 탭으로 잘못 인식되던 버그** — 실제 발주서 파일에 원본/참고용으로
  같이 남겨둔 "고객사 A 원본" 같은 탭도 "고객사 X" 패턴에 걸려서 읽으려다, 딥다이브 마커가 없다는
  이유로 `sheet_columns_missing` 경고가 세 업체 전부에서 잘못 떴다. 탭 이름에 "원본"이 들어있으면
  발주서 탭 대상에서 제외하도록 고쳤다.
- **xlsx→구글시트 변환을 실행마다 새로 하던 문제(속도 저하)** — 발주서/기준정보/공휴일/제품중량
  변환이 매번 몇 초~십수 초씩 걸리는데, 원본이 안 바뀌었어도 실행마다(특히 자동 감지 트리거가
  돌 때마다) 매번 재변환하고 있었다. 변환 사본을 원본 파일ID+수정시각과 함께 스크립트 속성에
  캐시해뒀다가, 원본이 실제로 안 바뀌었으면 재변환 없이 그대로 재사용하도록 고쳤다. 원본이 바뀌면
  캐시를 갱신하고 예전 사본은 정리한다.

## WritePlan.gs

- **변경 품목 강조 범위 버그** — 발주량이 바뀐 품목을 빨간 글씨로 강조할 때 품목코드·규격·구분
  3칸만 강조되고 정작 바뀐 숫자(합계·날짜별 배정값)는 강조가 안 됐다. 행 전체를 강조하도록 고쳤다.
- 파일명을 실행할 때마다 "N월_출고계획(통합)"으로 자동 변경(파일 탐색이 파일명 패턴 기반이라 필요).
- 헤더에 발주량 컬럼 추가, "구분(업체)"를 "구분(고객사)"로 변경.
- `ViewSwitch.gs`를 통합(파일 수 정리).
- **데모용 "기본 시트"와 실제 데이터 탭 분리** — 초기화(reset) 시 보여줄 빈 템플릿 탭과, 실제 발주
  데이터가 들어가는 "N월 출고계획" 탭을 분리했다. 실제 탭은 발주서 파일명 기준 연/월로 만들어져서
  달마다 따로 남고(다음 달 발주서를 미리 올려놔도 이번 달 탭이 안 지워짐), 오늘 날짜 기준 이번 달
  탭만 항상 1번째 탭으로 옮긴다 — `production-planning`이 파일의 **첫 번째 탭만** 읽기 때문에
  필수적인 처리다.
- **시트 쓰기가 품목마다 Range API를 따로 호출해서 느렸던 문제(자동 감지 후 반영까지 몇 분씩 소요)** —
  품목 행 하나당 값·숫자서식(2회)·SUM 수식까지 최대 5번씩 개별 호출하던 걸, 값·서식을 전부 배열로
  모았다가 `setValues`/`setNumberFormats`/`setFontWeights`/`setFontColors`/`setHorizontalAlignments`를
  딱 한 번씩만 부르도록 전면 재작성했다. 합계·소계 열도 SUM 수식 대신 메모리에 있는 값을 직접
  계산해서 채운다(수식 설정 자체가 느린 연산이라 값으로 대체).
- **신규/변경 품목 색상 구분** — 신규 발주 품목과 발주량이 변경된 품목을 똑같이 빨간 글씨로만
  강조하던 걸, 신규는 연두 배경+초록 글씨, 변경은 연주황 배경+주황 글씨로 나누고 표 아래에 색 범례
  문구를 추가했다(발표 데모에서 변경 사항이 한눈에 보이도록).

## OrderSnapshot.gs

- **"문서의 모든 시트를 삭제할 수 없습니다" 에러** — `forceRegeneratePlan()`으로 탭을 하나 지운
  뒤 스냅샷/지문 저장이 남은 마지막 탭을 삭제하려다 에러가 났다. 삭제 후 재생성 대신 `clear()`로
  내용만 지우는 방식으로 바꿨다.

## Allocate.gs

- 균등분배 로직이 자체적으로 usedDates를 추적하던 걸, `TruckBucket.gs`와 같은
  `_generateBaseDates_`를 쓰도록 바꿔서 공휴일 시프트 기준을 트럭버킷 타입과 일치시켰다.

## ProductionCapa.gs / MachineSchedule.gs

- 생산capa 계산을 "CAPA × 최대설비가동수"라는 단순 공식에서, `MachineSchedule.gs`가 새로 돌리는
  호기별 미니 생산스케줄링 시뮬레이션(우선순위·안되는품목·설비규격교체현황·최대설비가동수 반영)의
  누적치로 교체했다. 설비 경쟁으로 생산capa가 들쭉날쭉해지는 실제 상황을 반영한다.
- **검증 스킵 조건 버그(치명)** — `producedByDate`가 비어있는(이번 달 설비를 하나도 못 받은) 품목을
  "검증 데이터 자체가 없음"과 똑같이 취급해서 검증을 완전히 스킵(무제한 취급)했다. 실제로는 기초
  재고를 초과하는 배정이 경고 없이 통과되는 가장 위험한 케이스였다. 기초재고/적정재고가 둘 다 아예
  없는 품목만 스킵하고, `producedByDate`가 없으면 생산량을 0으로 취급하도록 고쳤다.

  단독으로 몰아 배정되던 문제를 다른 업체와 같은 방식으로 해결.
- 업체 표기를 `A사`/`B사`/`C사`에서 `고객사A`/`고객사B`/`고객사C`로 통일(연동 형식 정리).
- `MIN_SHIPMENT_KG`, `CHAT_WEBHOOK_URL` 등 설정값 추가.

## Util.gs

- **챗 알림 실패가 조용히 무시되던 문제** — `muteHttpExceptions`로 HTTP 에러가 예외로 안 터져서,
  잘못된 웹훅 URL을 등록해도 실패 사실을 알 방법이 없었다. 응답 코드를 직접 확인해서 성공/실패
  모두 로그에 남기도록 고쳤다.
- `ExecutionLog.gs`, `ChatNotify.gs`를 통합(파일 수 정리).
- 주석 문구를 "검증 경고"에서 "검증사항"으로 맞춤(Main.gs 등과 표현 통일).

## AutoTrigger.gs (신규)

- 발주서 파일은 이 스프레드시트 자체가 아니라 별도 드라이브 파일이라 `onEdit`/`onChange` 같은 단순
  트리거로는 변경을 못 잡는다. 시간 기반 트리거로 발주서 폴더를 주기적으로 확인해서, 파일이 새로
  생기거나 수정되면 `generatePlan('자동')`을 자동 실행하도록 추가했다(데모에서 "발주 들어오면
  자동 반영"을 보여주기 위함).
- **감지 지연 문제** — Apps Script 시간 기반 트리거는 `everyMinutes()`가 1분 미만을 지원하지 않아서,
  트리거 자체를 더 촘촘하게 걸 수 없다. 트리거는 1분마다만 실행되더라도, 그 안에서 5초 간격으로
  최대 55초 동안 반복 확인하도록 해서 체감 지연을 평균 5~10초로 줄였다(최악의 경우도 1분 이내).

## 더미데이터생성.gs

- 실제 기준정보.xlsx/제품 중량 파일에 있는 품목코드·단위중량을 그대로 써서, 참고파일을 연동했을 때
  단위중량 조회·생산capa 검증이 실제로 매칭돼서 동작하는지까지 테스트로 확인할 수 있게 했다.
